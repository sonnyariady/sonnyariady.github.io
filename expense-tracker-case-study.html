Portfolio Case Study • AI-Assisted Fullstack

Monthly Expense Tracker

From a .NET/C# background to React + Python through vibe coding and AI-assisted development

React 18 Python FastAPI SQLite Vite Recharts AI-Assisted

The Experiment

Can a developer whose primary stack is .NET/C# turn a simple household-finance idea into a working full-stack product using prompting, iterative review, testing, and engineering judgment?

01. Project Overview

The idea was intentionally simple: build a useful web application for recording, organizing, and analyzing monthly household expenses — then use the project to test a new development workflow rather than merely learn syntax in isolation.

1

Problem

Expense records are often fragmented across notes, chat messages, and spreadsheets. The application consolidates transactions into a searchable monthly view.

2

Product Goal

Create a usable dashboard with transaction management, monthly KPIs, visual analysis, filtering, and report export.

3

Learning Goal

Explore React and Python while applying familiar engineering concepts from .NET/C#: APIs, validation, persistence, and separation of concerns.

What the application actually does

  • Transaction management: Add, edit, delete, and review household expenses with dates, categories, types, notes, and IDR amounts.
  • Monthly analytics: Calculate total spending, transaction count, remaining budget, and estimated daily average.
  • Visual reporting: Display category distribution through a donut chart and expense-type distribution through a bar chart.
  • Finding and exporting data: Filter by month, year, category, or type; search by keyword; export current result set to CSV.
  • Static-demo resilience: Use FastAPI + SQLite backend when available, with an automatic browser LocalStorage fallback for a static public demo.

02. From Idea to Realization

AI generated code. Engineering judgment shaped the product. This project was an experiment in directing AI effectively, checking its output, and moving from an ambiguous idea to a coherent application.

01

Frame the idea

Define the user problem, essential screens, transaction fields, and useful monthly insights.

02

Prompt the solution

Ask Antigravity AI to propose and generate a React frontend and Python FastAPI backend.

03

Inspect the result

Review project structure, API contracts, state flow, database models, and generated business logic.

04

Test and iterate

Run the application, identify errors or awkward behavior, refine prompts, and adjust implementation.

05

Package the outcome

Document features, deployment options, limitations, and the AI-assisted development approach.

Working Principle

Prompting accelerated production, but did not remove accountability. The developer still had to decide what should exist, recognize whether the generated solution was sensible, test it, and explain how it works.

03. Technical Implementation

A lightweight architecture designed for both full-stack use and static public demonstration.

Architecture Overview

React + Vite Dashboard, forms, filters, charts
→
FastAPI REST endpoints and validation
→
SQLite Persistent transaction storage
Fallback Path for Static Hosting: When the backend is unavailable, the frontend automatically switches to browser LocalStorage so visitors on static public hosting can still test CRUD operations, filtering, and analytics.

Technology Choices

Layer Technologies Used
Frontend React 18, Vite, custom CSS, Lucide React, Recharts
Backend Python, FastAPI, Pydantic v2, SQLAlchemy, Uvicorn
Data SQLite for local persistence; LocalStorage fallback for static demos
API CRUD endpoints, filtered queries, master data, and monthly summary aggregation

Engineering Concepts Transferred from .NET/C#

API Contracts

Request and response schemas remain explicit with Pydantic v2 models even though the programming language changed.

Layered Responsibilities

UI components, API service calls, validation schemas, database models, and persistence layers are cleanly separated.

Business Rules

Monthly filtering, aggregation, budget progress calculations, and input validation still require deliberate logic.

Operational Thinking

CORS policies, deployment modes, seed demo data, and automatic failure fallbacks were designed as product concerns.

04. Application Walkthrough & Features

1

Choose Month & Year

Switch the reporting period instantly from the top toolbar dropdown menu.

2

Review Monthly KPIs

Monitor total spending, budget remaining, daily average spending, and transaction count at a glance.

3

Interpret Charts

Compare spending breakdown by category (Donut chart) and expense type (Bar chart).

4

Manage & Export Data

Add new transactions, edit existing records, delete entries, or export filtered period data to CSV.

Transaction Management & Data Entry Flow

When clicking + Tambah Pengeluaran, a modern modal appears prompting for Title, IDR Amount, Date, Category (e.g. Makanan & Bahan Pokok, Tagihan & Utilitas, TopUp E-Wallet, Transportasi & Bensin), Type (Belanja, Tagihan, Jajan, Ongkos, Topup), and optional notes.

A single save action updates the SQLite database or LocalStorage, instantly updating the KPIs, donut category chart, bar expense-type chart, and transaction list in real time.

05. Role, Lessons & Next Steps

Product Direction

Defined the application goal, expected user journey, transaction model, and reporting features.

Prompt Direction

Translated ideas into instructions and iteratively refined the AI-generated codebase.

Technical Review

Examined generated React components, FastAPI endpoints, data models, and calculation logic.

Validation & Testing

Executed the application, verified workflows, fixed edge cases, and validated fallback behavior.

Key Lessons Learned

  • Strong requirements produce better AI output: Precise specifications yield clean architecture.
  • Familiar architecture concepts transfer: Separation of concerns, validation, and API contracts apply regardless of language.
  • Generated code still requires review: Engineering judgment is essential to inspect edge cases and security.
  • A working demo is invaluable: Live interactive prototypes communicate value better than static prompts.
  • Transparency builds credibility: Honesty about AI collaboration highlights real engineering leadership.

Portfolio Positioning

Monthly Expense Tracker — an AI-assisted full-stack experiment by a .NET/C# developer exploring React and Python. The project demonstrates the ability to turn an idea into a functioning product, transfer engineering principles across stacks, and use AI as a development accelerator without misrepresenting authorship.
